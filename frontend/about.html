About EduCore Student Management System

EduCore is a full-stack web application designed to streamline academic onboarding, student record administration, profile photo management, password recovery, and automated credential delivery. Built with a modern responsive frontend and a high-performance FastAPI backend, the platform enforces strict data integrity and role-based security.

1. Functional System Requirements

Authentication, RBAC & Password Recovery

  • Separate login workflows and protected endpoints for Administrators and Students.
  • Token-based session authentication and SHA-256 password hashing.
  • Self-service Forgot Password reset flow emailing temporary credentials via Gmail SMTP.

Student Onboarding & Profile Photos

  • Public registration form capturing full name, email, department, GPA, and optional profile photo.
  • Pending request queue allowing administrators to review, approve, or reject applicants.
  • Students can view their profile badge/photo and update their profile picture or password anytime.

Department Management & Roster Filtering

  • Standardized academic department selection across registration and administration views.
  • Real-time admin filtering by academic department and search by name, email, or Student ID.

Automated Email & Strict Input Validation

  • Integration with Gmail SMTP (TLS on port 587) using App Password authentication.
  • Pydantic schema validation enforcing valid email formats, GPA bounds (0.0 – 4.0), and duplicate prevention.

2. Technical & Environment Requirements

Component Technology / Requirement Purpose
Backend Runtime Python 3.10+ (Tested on Python 3.13) Core server execution environment
API Framework FastAPI, Uvicorn, Pydantic, email-validator RESTful API routing, ASGI server, and strict data validation
Database SQLite 3 (students.db) Relational storage for admins, students, photos, and registration requests
Frontend Stack HTML5, Tailwind CSS, Vanilla JavaScript (ES6+) Responsive user interface, FileReader photo encoding, and Fetch API calls
Mail Server Google Account with 2-Step Verification & 16-char App Password Outgoing SMTP credential & password reset delivery via smtp.gmail.com:587

3. Non-Functional Requirements

  • Security: Plaintext passwords are never stored in the database; all admin routes verify authorization headers before executing database mutations.
  • Fault Tolerance: Email dispatch is wrapped in exception handling so temporary network or SMTP interruptions do not crash the API.
  • Usability & Responsiveness: Clean, accessible UI layout adaptable to desktop and mobile viewports with immediate feedback banners.
